# 家庭 Agent 基础设施——设计规格

日期：2026-07-24
状态：已获用户批准

## 1. 愿景与边界

建立一个本地优先的家庭 Agent 中枢，连接公共智能屏、学生平板、家长 App、Web、微信和未来各房间感知节点。Agent 通过受限工具使用设备和家庭业务能力，不直接获得 shell、数据库或文件系统的通用权限。

首个业务场景是纸质数学作业检查，见 [家庭作业 Agent 原型规格](2026-07-24-family-homework-agent-prototype.md)。本规格只定义业务共用的服务、节点、身份、模型、语音和家庭历史边界。

## 2. 家庭与应用

- 家庭成员：2 位同权限家长、2 位孩子（5 岁、10 岁）、1 位老人。
- 屏幕、摄像头和房间节点不永久绑定某个成员；当前成员是可过期的会话状态。
- 公共智能屏、学生 Android App 和家长 App 为独立应用，共享协议、SDK 和数据模型。
- 学生端首期为 Android 学习平板，使用自身摄像头提交作业。
- 家长 App 使用 Flutter 目标 Android+iOS，首期先验收 Android。
- 家长功能交付顺序：Web → Flutter 家长 App → 微信通知/确认 → 微信作业转发/对话 → 必要时微信小程序。

## 3. Monorepo 布局

使用同一仓库、多独立应用和共享包；采用渐进迁移，原型开始时不搬动现有 Flutter 工程。

```text
<repo>/                       现有 smart_display Flutter 工程
apps/
  student_app/               独立 Android 学生端
  parent_app/                Flutter Android/iOS 家长端
packages/
  home_agent_client/         服务端 API 客户端
  node_protocol/             节点消息与能力模型
  shared_models/             共享 DTO
  shared_ui/                 可复用 Flutter 组件
home_agent/                  独立 Python 项目
  home_agent_server/         API、Agent、身份、历史、存储
  linux_room_node/           Linux 硬件节点进程
  tests/
daemon/                      现有照片索引进程，保持独立
```

## 4. 总体架构

```text
Web / Parent App / WeChat / Student App / Smart Display
                          │ HTTP + WebSocket
                          ▼
                 Home Agent Server
  认证 / 任务 / Agent / 工具 / 身份 / 历史 / 审计
        │                    │                 │
        ▼                    ▼                 ▼
 SQLite+本地文件      Model Registry       Room Nodes
                         GLM/Kimi/K3/本地     Linux/Android/未来节点
```

- Home Agent Server 是家庭业务和历史索引的权威源。
- Linux Room Node 即使与 Server 同机也作为独立进程，使用与远程节点相同的协议。
- 现有照片 daemon 不承载家庭 Agent 业务。

## 5. 房间节点与能力调度

节点注册 `nodeId`、`roomId`、版本和能力。设备不按“作业摄像头”或“观察摄像头”写死用途，而是报告分辨率、对焦、预览、是否可移动等属性。业务提交需求，调度器根据在线状态、房间和属性选择任意满足条件的设备。

### 5.1 通信

- 节点主动连接 Server 的持久 WebSocket。
- JSON 帧：注册、心跳、能力、命令、状态和识别事件。
- 二进制 WebSocket 帧：实时对话音频。
- HTTP multipart：拍照结果和归档媒体片段。
- 每条消息带 `nodeId`、`roomId`、`sessionId`、序号和协议版本。
- 节点断线自动重连；断线不代表成员离开。
- 未来实时视频通话使用 WebRTC，不复用归档上传链路。

### 5.2 首期硬件

- 第一个房间为客厅。
- 家庭服务器为当前 Ubuntu 开发机：Ryzen 7 2700、60 GiB RAM、GTX 1070 Ti。
- Linux Room Node 连接 USB 摄像头、USB 麦克风阵列和扬声器。
- 客厅 USB 摄像头无法覆盖作业桌；Android 学习平板摄像头是首期作业提交的主要设备，但不在业务层写死。
- 设备型号到货后通过 USB/V4L2/ALSA 能力探测确认。
- 当前 NVIDIA 内核模块 `580.159.03` 与用户态库 `580.173.02` 不一致，本地 GPU 模型验收前必须恢复 `nvidia-smi`。

## 6. 家庭身份与权限

### 6.1 人脸/声纹录入

- 家长创建成员档案并选择任意满足能力的节点录入多角度人脸、指定短句和自然语音。
- 向量在家庭服务器本地生成与保存，由家长确认、纠错、重录或删除。
- 只有高置信度且经多模态/家长确认的新样本才能渐进更新，避免错误自强化。
- 孩子声纹允许多时期原型，不假设声音永久不变。

### 6.2 日常识别

```text
摄像头 → 人脸/位置 ──┐
                           ├→ 身份融合 → member/session
阵列音频 → VAD → 说话人分离 → 声纹 ─┘
```

- 支持多人轮流/重叠说话；融合人脸、声纹、房间、位置和会话上下文。
- 不确定时询问确认，不猜测；手动/语音选择仅是录入、纠错和失败兜底。
- 人脸/声纹只表示身份判断，不直接授予管理权限。

### 6.3 认证授权

- 2 位家长使用独立账号，权限相同；Web/家长 App 首期使用用户名密码。
- 节点使用一次性配对码加入家庭，然后持有独立设备密钥。
- 孩子可查看、开始和提交自己的任务，不能修改任务或参考答案。
- 删除、修改、展示完整答案等敏感操作必须由已认证家长端执行/确认。
- 所有写工具和敏感读取记录 actor、device、reason 和时间。

## 7. 本地感知与语音

- 节点本地持续做轻量人/脸存在、语音活动和唤醒词检测，事件触发后才做高成本身份处理。
- 节点提供可见状态和不可被 Agent 绕过的隐私关闭开关。
- 被动状态不进行完整语义理解；唤醒词、按钮或经允许的主动问候进入活动会话。
- 活动会话中不需每句重复唤醒，支持多人轮流对话和随时打断 TTS。
- 麦克风阵列优先使用硬件 AEC/波束成形；软件链路必须处理扬声器回声。
- 首期本地 ASR 和本地 TTS 必须独立跑通；云端 ASR 只预留适配，edge-tts 作为 TTS 可配置降级。
- 家庭历史录音仅在回溯时按需转写。
- Agent 声音、唤醒词和人格为初始化/运行配置，不在基础代码中写死。

## 8. 家庭历史录制与回溯

### 8.1 录制和归档

- 原型客厅节点连续保存音频和视频，按短片段切分，不持续执行完整 ASR 或视频语义理解。
- 可建立时间、房间、设备、存在、移动和声响水平等轻量索引。
- 默认 7 天滚动覆盖，家庭服务器总配额 200 GB；书签片段不自动删除。
- 节点本地采集、编码和短期缓冲，媒体片段异步上传家庭服务器集中归档。
- 断网时继续缓冲，恢复后补传；服务器统一执行配额、过期、书签和权限。
- 未来每房间可配置关闭、仅音频、仅事件录像或连续录制。

### 8.2 按需回溯

- `history.search(room, time_range, event_filters)` 定位片段。
- `history.inspect(clip_ids, reason)` 对选定片段做 ASR/人脸/声纹/视频理解。
- 只有成员明确询问、家长要求、Agent 执行明确任务时缺少必要上下文，或非语义异常事件时可回溯。
- 不允许 Agent 无目标浏览历史；每次回溯记录 reason、actor、时间范围、片段、模型和结果。

## 9. 模型注册与路由

- GLM、Kimi、K3、本地模型和未来 provider 平等注册，不在业务代码中预设主/备或固定用途。
- provider 只处理协议/厂商差异；业务申请 `chat`、`vision`、`tools`、`structured_output`、`reasoning`、`long_context` 等能力。
- 启动时做模型列表、健康和能力检测；支持自动路由、手动选择和“换模型复核”。
- 作业检查原型默认单模型；低置信或不一致结果交家长。
- 原型允许配置 GLM/Kimi Coding Plan 端点，不在代码中限制套餐类型。
- `base_url`、`model`、协议和能力由配置提供；API Key 只从环境变量/密钥存储读取。

## 10. 数据存储

- Home Agent 使用独立 SQLite，开启 WAL 和事务。
- 照片、音频和视频使用本地文件，SQLite 保存元数据、hash 和引用。
- 数据访问经 repository 层，保留未来迁移 PostgreSQL 的可能。
- 与照片 daemon 数据库完全分离，并定义导出、备份和恢复边界。

## 11. 分阶段交付

1. **仓库骨架与协议**：`home_agent/`、Server/Node 进程、SQLite、认证、节点注册与假设备。
2. **Linux 客厅节点**：USB 摄像头、麦克风阵列、扬声器、断线缓冲和媒体归档。
3. **本地身份**：5 位成员录入、人脸、VAD、说话人分离、声纹和身份融合。
4. **本地语音闭环**：唤醒、本地 ASR、Agent 对话、本地 TTS、打断和 AEC。
5. **家庭历史**：7 天/200 GB 归档、书签、搜索、按需理解和审计。
6. **学生 Android App + 作业闭环**：任务、摄像头、提交、检查、提示和 Web 家长审核。
7. **家长 Android App**：登录、任务、报告、设备、身份和通知。
8. **微信与扩展节点**：逐项落单独规格。

每一阶段必须可独立验收和降级，不以后续阶段完成为启动条件。

## 12. 延后决策

基础建设阶段不定死 Agent 名字、形象、人格、声音、唤醒词、沟通风格、主动聊天规则、提醒强度和学习计划策略。这些属于初始化/运行政策。硬件专有能力待设备到货后探测；iOS 发布、微信形式、WebRTC、PostgreSQL 和模型微调均延后。

## 13. 实施前条件

1. 用户审阅并批准本规格。
2. 为阶段 1 单独编写实施计划，不一次开工全部阶段。
3. 涉及 GPU 的阶段开始前修复 NVIDIA 驱动/库版本不一致。
4. 真实硬件集成前记录设备型号、USB/V4L2/ALSA 枚举结果和硬件 AEC 能力。
5. 凭据只通过环境变量/密钥存储配置，不写入仓库。
